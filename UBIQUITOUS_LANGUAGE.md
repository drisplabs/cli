# Ubiquitous Language

Domain glossary for Athena's workflow execution — the Turn Protocol and its runner. Extracted from analysis of `src/core/workflows/` and `src/harnesses/claude/`.

## Execution units

Definitions below are reconciled against the official vendor docs (see [Cross-walk](#cross-walk-to-official-terminology)). Where Athena's current code naming clashes with the vendor meaning, the recommended term is given and the clash is noted in [Flagged ambiguities](#flagged-ambiguities).

The four execution units nest. **Feed Run** is a parallel UI projection, not a level in this tree:

```
Athena Session        durable work-unit; one ~/.config/athena/sessions/<id>/session.db   (`session` table)
  └── Workflow Run     one loop execution; runId UUID                                     (`workflow_runs`)
        └── Turn       one `claude -p` / Codex `thread.run`                               (startTurn/TurnExecutionResult)
              └── Agent Session   vendor session/thread; spans resumed Turns, resets at Handover  (SessionController)
```

| Term               | Definition                                                                                                                                                                                                                                                                                                                                                               | Aliases to avoid                      |
| ------------------ | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ | ------------------------------------- |
| **Athena Session** | The durable work-unit: one `~/.config/athena/sessions/<id>/session.db` (the `session` table). **Contains many Workflow Runs.** This is what the `athena-<id>` / `.athena/<id>/` identity and `session.db` identify — _not_ a vendor session and _not_ a single Workflow Run.                                                                                             | Session, vendor session, Workflow Run |
| **Workflow Run**   | One execution of a whole workflow — the loop spanning every Turn from start to a terminal status. Identified by a `runId` UUID (`workflow_runs` row, FK `session_id → session`); **many per Athena Session.**                                                                                                                                                            | Run, job, task, **session**           |
| **Turn**           | One agent execution — a single `claude -p` invocation / one Codex `thread.run` — that runs one prompt to completion. The canonical unit. A Turn is a fresh spawn, a **resume** of the prior Agent Session (Nudge / Retry / human-reply), or the fresh session that opens a **Handover** — all three are Turns.                                                           | Iteration, session, call, run         |
| **Agent Session**  | The vendor-native conversation context a Turn runs in: a Claude Code _session_ or a Codex _thread_. It **spans multiple Turns** when they resume it (`--resume` / `--continue`) and **resets at a Handover** (a fresh session seeded from the Handoff file). Within a resumed span its own context carries continuity; across a Handover, the Handoff file + Journal do. | Conversation, thread (use per-vendor) |
| **Iteration**      | The integer index of a Turn within a Workflow Run (Turn 1, 2, …). Not a unit of its own — _one iteration == one Turn_. Every Turn — fresh, resumed, or post-Handover — ticks it; `maxIterations` is the single runaway ceiling (→ `awaiting_attention`). Not a vendor term.                                                                                              | Cycle, round, pass                    |
| **Feed Run**       | The UI/timeline projection of activity bounded by a trigger (prompt submit, resume, clear, compact); distinct from a Workflow Run. `feed_events.run_id` is unrelated to `workflow_runs.id`.                                                                                                                                                                              | Run                                   |

## State & continuity

| Term                       | Definition                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                       | Aliases to avoid                                       |
| -------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------ |
| **Journal**                | The on-disk markdown **index** file carried across Turns: current state, open loops, next action, and (ADR 0015) a pointer into the rest of the **Dossier**. Durability against a killed Turn, the seed a **Handover** hands the fresh session (with the Handoff file). Revised in place; cold detail **sheds** out of it rather than accreting inside it. No longer the _sole_ continuity mechanism — a resumed **Agent Session** also carries its own context. Lives at `.athena/<session_id>/journal.md` (`DEFAULT_JOURNAL_PATH`); was the **Tracker** (`tracker.md`) before #185 — see [Deprecated names](#deprecated-names) | Tracker (pre-0.6 name), log, state file, progress file |
| **Dossier**                | `.athena/<session_id>/` as a whole: the **Journal** plus everywhere it can shed cold detail once shedding earns its keep — **Unit Record**s (`units/<slug>.md`), `orientation.md`, and the **Handoff file** chain (`handoff/NNN.md`). Emergent, not mandatory: a Run that never trips a shed trigger has a Dossier of exactly one file, identical to before ADR 0015 (§1-§2)                                                                                                                                                                                                                                                     | Session dir, workspace                                 |
| **Unit Record**            | `units/<slug>.md` — the whole verbatim detail (contract, problem, design + rationale, build state, gate evidence) of one closed **unit** — a bounded piece of the plan that reaches its own closed state while the Run keeps going, e.g. one issue in a multi-issue epic — moved out of the Journal by a **shed**: cut → paste → pointer, never a summary. The Journal keeps one index row and a relative path (ADR 0015 §3-§4). ADR 0015 §1 calls this sink "the journal" in the diary sense; since #185 **Journal** names the index file and this is the **Unit Record**                                                       | Unit file, journal (bare), tracker section             |
| **Handoff file**           | A per-**Handover** artifact the `handoff` skill writes in a forked Turn at compaction time: a conversation-derived summary (task + status, decisions made, open questions, files touched by path, suggested next-step skills). Seeds the next fresh Turn **alongside** the Journal — the Journal is the durable cross-Turn index; the Handoff file is ephemeral (temp dir) and carries the in-flight context a Journal checkpoint omits. Lives in the **Dossier** at `handoff/NNN.md`, a chain retaining the last two, newest mandatory-read (ADR 0015 §8)                                                                       | Handoff doc, compaction summary                        |
| **Skeleton**               | The placeholder Journal the runner writes before Turn 1, marked `<!-- JOURNAL_SKELETON -->`                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                      | Template, stub                                         |
| **Terminal Marker**        | The last-non-empty-line sentinel by which a Turn declares how it ended. Exactly two: `WORKFLOW_COMPLETE` → the terminal `completed`; the **Needs-human marker** → the non-terminal `awaiting_attention`. Only the last non-empty line is authoritative                                                                                                                                                                                                                                                                                                                                                                           | Flag, tag, signal                                      |
| **Needs-human marker**     | `<!-- NEEDS_HUMAN: reason -->` — **the one way a Turn asks for a person**: a question only they can answer, or an external blocker only they can clear. Maps to the **non-terminal** `awaiting_attention` (alert + resumable), _not_ a dead end — so despite the category name it does not end the Run. Named after the `needs_human` frame in `@drisp/protocol`. The pre-0.6 spelling `WORKFLOW_BLOCKED` still resolves to the same outcome for one release and logs a deprecation when seen (`DEFAULT_NEEDS_HUMAN_MARKER`, `LEGACY_BLOCKED_MARKER`)                                                                            | Blocked marker, WORKFLOW_BLOCKED (pre-0.6 name), block |
| **Composed System Prompt** | The per-run generated file (`.composed-system-prompt.md`) = Protocol + Workflow Instructions, delivered to the agent                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                             | Workflow.md, system prompt, prompt file                |
| **Run section**            | The banner a **Workflow Run** start appends to the Journal (`**Run**: id`, `**Goal**: goal`), first demoting any prior **Terminal Marker** already on the Journal into an inert historical note (`demoteTerminalMarkers`) — no Run inherits a predecessor's verdict. A wake continues the same Run and opens no new section (ADR 0015 §5, landed in #171)                                                                                                                                                                                                                                                                        | Run banner, session header                             |

## The protocol

| Term                   | Definition                                                                                                                                                                                                                                                                                                                          | Aliases to avoid                                                    |
| ---------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------- |
| **Turn Protocol**      | The agent-facing rules governing how each memoryless Turn reads, advances, and writes the Journal. Formerly "Stateless Turn Protocol" — renamed by ADR 0015 §11; see [the misnomer note](#flagged-ambiguities)                                                                                                                      | State machine, the loop, workflow protocol, Stateless Turn Protocol |
| **Orient**             | The protocol phase for Turn 1: replace the Skeleton, explore, and build the plan                                                                                                                                                                                                                                                    | Setup, init, bootstrap                                              |
| **Orientation** (file) | `orientation.md` in the **Dossier** — cross-unit knowledge, revised in place rather than shed into. Two sections: **Established** (decisions, never decay, only explicitly superseded) and **Observed** (facts anchored `file.ts:123`-style, revalidated before reliance). Distinct from **Orient**, the Turn-1 phase (ADR 0015 §6) | Orientation doc, knowledge file                                     |
| **Execute**            | The protocol phase for Turn 2+: resume work from where the Journal says                                                                                                                                                                                                                                                             | Run, continue, work                                                 |
| **End**                | The protocol phase that reconciles the Journal and writes a Terminal Marker if finished                                                                                                                                                                                                                                             | Finish, complete                                                    |
| **Continue Prompt**    | The lightweight user prompt sent on Turn 2+ telling the agent to read the Journal                                                                                                                                                                                                                                                   | Resume prompt                                                       |

## The runner

| Term                 | Definition                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                               | Aliases to avoid                                                            |
| -------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | --------------------------------------------------------------------------- |
| **Runner**           | The component that drives the loop: owns the single Iteration counter, spawns Turns, and assigns the terminal Run Status the Terminal Outcome hands it                                                                                                                                                                                                                                                                                                                                                                                                                                                   | Driver, orchestrator, executor                                              |
| **Turn Runner**      | The single per-adapter lifecycle that executes one Turn (spawn/subscribe → accumulate → finalize into a `TurnExecutionResult`). Both session-controller shapes — the interactive Ink hook and the non-interactive `drisp run` factory — run Turns through it. For Codex this is `runCodexTurn`; see ADR 0007                                                                                                                                                                                                                                                                                             | Turn loop, turn executor, spawner                                           |
| **Journal Reader**   | The read-only, stateless inspector of the Journal: pure functions (`parseJournalState` / `readJournal`, in `journalReader.ts`) that turn Journal text into a Journal State. Holds no loop state of its own                                                                                                                                                                                                                                                                                                                                                                                               | Loop Manager, state manager                                                 |
| **Journal State**    | What the Journal's text says about progress — a pure function of the Journal file: completed, blocked (+ reason), misplaced-terminal-marker, skeleton-not-replaced. The Iteration limit is applied by the Runner, not derived here                                                                                                                                                                                                                                                                                                                                                                       | Loop State                                                                  |
| **Terminal Outcome** | The single owner (`resolveTurnOutcome`, `terminalOutcome.ts`) that maps a Journal end-state to the Runner's decision after a Turn: continue, or stop with a Run Status + human message. Replaces the former `LoopStopReason` enum                                                                                                                                                                                                                                                                                                                                                                        | Stop Reason, exit reason                                                    |
| **Run Status**       | The outcome of a Workflow Run. Terminal: `completed`, `failed`, `cancelled`. Non-terminal: `awaiting_attention` — suspended until a **human** replies, which **resumes** the intact Agent Session. `blocked` and `exhausted` are **no longer emitted**: a declared `NEEDS_HUMAN` and the `maxIterations` ceiling both route to `awaiting_attention` (both stay valid on historical rows). (Transient-failure **Retry** also keeps a Run alive, but it stays `running` and wakes automatically on a backoff timer — the split is "Athena can fix it alone" vs "needs a human," not resumable vs terminal) | State, result                                                               |
| **Workflow**         | The reusable, installed definition (instructions + plugins + loop config) that a Workflow Run executes                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                   | Recipe, template, pipeline                                                  |
| **Workflow Upgrade** | Replacing an installed Workflow's on-disk files in place with a new version                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                              | Update, sync, install                                                       |
| **Compaction**       | Summarizing a Turn's conversation history when context fills; the Composed System Prompt survives it because it rides the system-prompt channel                                                                                                                                                                                                                                                                                                                                                                                                                                                          | Summarization, truncation, handoff                                          |
| **Handover**         | The compaction-time procedure that replaces in-place vendor **Compaction** for a Workflow Run: when a Turn crosses **`maxTurnTokenCount`** (set well under the model window, for headroom) `PreCompact` is **blocked**, the live conversation is **forked** (`--fork-session`, autocompact disabled), the **`handoff` skill** distills it into a **Handoff file**, the fork is discarded, and a **fresh** Turn (new Agent Session) is seeded with that file plus the Journal. The only transition that resets context instead of resuming — every other continuation resumes the intact session          | Auto-compaction (Handover replaces it), respawn (the bare fresh-Turn spawn) |
| **Retry**            | Automatic re-attempt after a _transient_ failure (`rate_limit`/`overloaded`/`server_error`): the Runner waits a backoff, then **resumes** the same **Agent Session** (`--continue`) — not a fresh Turn — up to a retry cap. The Run stays `running`; exhausting the cap escalates to **Needs-attention**. Timer-woken (automatic), unlike Needs-attention (human-woken)                                                                                                                                                                                                                                  | Reattempt                                                                   |
| **Nudge**            | The Runner's corrective **resume** of a Turn that exited **without** a terminal marker and without an error — an undeclared / premature stop ("done with X — want me to continue?"). Re-prompts the same **Agent Session** to finish or to declare a marker, bounded by a cap; exceeding the cap escalates to **Needs-attention**. Distinct from **Retry** (transient failure) and **Handover** (context limit)                                                                                                                                                                                          | Continue-prompt, poke                                                       |
| **Needs-attention**  | What Athena emits when the machine cannot proceed alone: a declared `NEEDS_HUMAN` (question / blocker) or an `AskUserQuestion` elicitation, a **hard** failure (`auth`/`billing`/`invalid_request`/`model_not_found`), or an exhausted cap/ceiling (Retry cap, Nudge cap, `maxIterations`). Suspends the Run in the non-terminal `awaiting_attention` until a human replies (via the **Relay** path), which **resumes** the intact Agent Session with that reply. Human-woken, unlike **Retry**; an _undeclared_ markerless clean stop is a **Nudge**, not this                                          | Attention request, alert                                                    |

## Headless entrypoint and isolation presets

| Term                 | Definition                                                                                                                                                                                                                                                                                                                                                                                                                                                                         | Aliases to avoid                                       |
| -------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------ |
| **`drisp run`**      | The headless, CI-shaped command that starts (or, with `--continue`, wakes) a **Workflow Run** for one prompt and exits with a structured code (`RUN_EXIT_CODE`). `drisp exec` is its deprecated alias: identical behaviour plus a one-line stderr notice, removed in 0.7.0. The JSONL event names (`exec.started`, `exec.warning`, `exec.completed`, `exec.error`) are a wire contract and keep their spelling                                                                     | exec (pre-0.6 name), headless mode (bare), CI mode     |
| **Isolation preset** | The named level of autonomy a Turn's harness process gets, least to most: **`guarded`** (default — core code tools only, no web, no subagents), **`standard`** (adds web, subagents, skills, and plugin MCP), **`autonomous`** (everything `standard` allows plus notebooks; on Codex, full access and never asks). Chosen with `--isolation`; a **Workflow** may raise the level it needs, never lower the user's. Harness-neutral (`HarnessProcessPreset`), realised per harness | strict / minimal / permissive (pre-0.6 names), sandbox |

## The wire

The runner ↔ hub contract lives in the `@drisp/protocol` workspace package (`packages/protocol`), which speaks this glossary's vocabulary on the wire. Terms it needed that the runner sections above did not name:

| Term                 | Definition                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                               | Aliases to avoid                                          |
| -------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | --------------------------------------------------------- |
| **Interruption**     | _Why_ a Workflow Run parked in `awaiting_attention` — the payload of a **Needs-attention** escalation, carried to the hub on a `needs_human` frame. Exactly one of: a declared `NEEDS_HUMAN` marker (`blocked`, with its reason), an elicitation the agent raised (`question`, addressed by `requestId` when the request is still pending; an unattended Run interrupts the Turn instead, so its question carries no `requestId` and is woken with a **Steer**), a **hard** failure (`hard_failure`, with its failure code), or an exhausted cap/ceiling (`cap_exhausted`: Retry cap, Nudge cap, `maxIterations`). Resolved by a human reply, which **resumes** the intact Agent Session | Block reason, attention reason, alert                     |
| **Steer**            | A human turn text sent _into_ a Workflow Run (`steer` frame): wakes a Run parked on an **Interruption** that is not a question (a question is answered with an `answer`), or is carried into the next **Turn** of a running one. The human-reply half of **Needs-attention**, given a name on the wire                                                                                                                                                                                                                                                                                                                                                                                   | Nudge (that is the Runner's own re-prompt), message, chat |
| **Protocol version** | The single integer both sides carry on their first (`hello`) frame; `@drisp/protocol` exposes the one it speaks as `PROTOCOL_VERSION`. Bumps only on an incompatible frame change — a new optional field or a new frame name does not bump it                                                                                                                                                                                                                                                                                                                                                                                                                                            | Schema version, API version                               |

## Cross-walk to official terminology

How Athena's units map to what Anthropic and OpenAI actually define in their docs. The headline: **Athena's `session` (the `athena-<id>` / `session.db` / `.athena/<id>/` identity) is NOT a vendor session** — it is the durable **Athena Session**, the work-unit container that holds _many_ **Workflow Runs**. A vendor "session"/"thread" is per-Turn and ephemeral here (an **Agent Session**).

| Athena concept                                   | Claude Code (Anthropic)                                                          | Codex (OpenAI)                                                                                                         | Vendor status                                                                     |
| ------------------------------------------------ | -------------------------------------------------------------------------------- | ---------------------------------------------------------------------------------------------------------------------- | --------------------------------------------------------------------------------- |
| **Turn** (`startTurn`, `TurnExecutionResult`)    | _turn_ — used informally for one prompt→response cycle; **not** formally defined | _turn_ — **formally defined**: `turn.started` / `turn.completed` / `turn.failed`; one `thread.run(prompt)` == one turn | Formal in Codex, informal in Claude                                               |
| **Agent Session** (one fresh per Turn)           | _session_ — saved conversation tied to a dir, resumable by ID, spans processes   | _thread_ — resumable conversation, `startThread` / `resumeThread`, forkable                                            | Formally defined by both                                                          |
| **Athena Session** (`athena-<id>`, `session.db`) | — _(no native equivalent)_                                                       | — _(no native equivalent)_                                                                                             | Athena-only durable container; **do not call it a "session"** in the vendor sense |
| **Workflow Run** (`runId`, `workflow_runs`)      | — _(no native equivalent)_                                                       | — _(no native equivalent)_                                                                                             | Athena-only loop execution; many per Athena Session                               |
| **Iteration** (loop index)                       | "the agentic loop" (phases: gather context → act → verify)                       | the agent loop                                                                                                         | "iteration" is **not** a vendor term                                              |
| **Message** (sub-Turn)                           | `message` — user/assistant/`tool_use`/`tool_result`; + `model request`           | _item_ — agent message, reasoning, command exec, tool call, …                                                          | Formally defined by both                                                          |
| **Compaction**                                   | _compaction_ — summarizes history **within the same session**; no new session    | _compact_ — same idea                                                                                                  | Formally defined; same-session                                                    |

Key consequences:

- **One prompt→completion cycle = a Turn** in all three vocabularies. Athena's `Turn` is correct and the unit to standardize on.
- A vendor **session/thread can hold many turns**, and Athena now relies on that: a Turn either spawns a fresh Agent Session or **resumes** the prior one (`--resume` / `--continue`), so one Agent Session spans the Turns that resume it and resets only at a **Handover**.
- **Iteration** is just the Turn's index; it is not a separate thing to model. Prefer "Turn N".
- A **Compaction** stays inside one Agent Session (one Turn) — but inside a Workflow Run it is intercepted at `PreCompact` and replaced by a **Handover**, which does end the Turn and start a fresh Agent Session.

## Relationships

- An **Athena Session** is the durable container (`session` table, one `session.db`) that holds one or more **Workflow Runs** (`workflow_runs`, FK `session_id → session`).
- A **Workflow Run** executes exactly one **Workflow** and consists of one or more **Turns** (numbered by **Iteration**).
- Each **Turn** runs in an **Agent Session** (a Claude session / Codex thread) — fresh on Turn 1 and after a **Handover**, resumed for a **Nudge**, a **Retry**, or a human reply — and reads and writes the single shared **Journal**.
- The **Runner** writes the **Skeleton** before the first **Turn**; the agent must replace it during **Orient**.
- The agent ends a **Workflow Run** by writing a **Terminal Marker**; the **Runner** trusts it unconditionally and maps it to a **Run Status**.
- The **Composed System Prompt** = **Turn Protocol** + the **Workflow**'s instructions, regenerated on every **Workflow Run**.
- In a Workflow Run, **Compaction** is intercepted and replaced by a **Handover**, which ends the **Turn** and starts a fresh one; an unintercepted **Compaction** stays inside one **Turn** and starts a new **Feed Run**.
- Only the last non-empty line of the **Journal** is an authoritative **Terminal Marker**.

## Example dialogue

> **Dev:** "When a **Workflow Run** starts, is the **Journal** already there for the first **Turn**?"

> **Domain expert:** "The **Runner** writes a **Skeleton** first. **Turn** 1 reads it, sees `JOURNAL_SKELETON`, and goes into **Orient** — its job is to replace that **Skeleton** with a real plan before doing anything else."

> **Dev:** "And **Turn** 2 — does it re-read the whole **Workflow**? Does it resume **Turn** 1's **Agent Session**?"

> **Domain expert:** "It depends why Turn 1 ended. If it stopped short without a marker, or hit a transient failure, **Turn** 2 **resumes** Turn 1's **Agent Session** — same conversation, context intact. If Turn 1 crossed the token bound, a **Handover** ran, and Turn 2 is a brand-new **Agent Session** seeded with the **Handoff file** plus the **Journal**. Either way the **Composed System Prompt** carries the **Protocol** into every **Turn**, and the `athena-<id>` stays the same across both — that ID is the **Athena Session** (the durable container), not a vendor session. Within it, this loop is one **Workflow Run**."

> **Dev:** "What if context fills up mid-**Turn** and a **Compaction** happens — does the **Protocol** get lost?"

> **Domain expert:** "Inside a **Workflow Run** it doesn't compact at all — `PreCompact` is blocked and a **Handover** runs instead: the conversation is forked, the `handoff` skill writes a **Handoff file**, and a fresh **Turn** picks up from that plus the **Journal**. The **Protocol** survives either way, because the **Composed System Prompt** rides the system-prompt channel, not the conversation history."

> **Dev:** "So when does the **Workflow Run** actually stop?"

> **Domain expert:** "It _finishes_ when the agent writes `WORKFLOW_COMPLETE` on the **Journal**'s last line. If it writes `NEEDS_HUMAN` instead, or a hard failure or a bound trips, the Run **suspends** in `awaiting_attention` — non-terminal, waiting on a human, then resumed. The terminal statuses are `completed`, `failed`, and `cancelled`; `blocked` and `exhausted` are no longer emitted."

## Flagged ambiguities

- **"Session" collides head-on with the vendor meaning — this is the worst one.** Anthropic and OpenAI both formally define _session_/_thread_ as a **resumable conversation context** (one agent, spanning processes). Athena uses `session` (`athena-<id>`, the `sessions/` dir, `session.db`, `.athena/<sessionId>/`) for the **durable work-unit** — what this glossary calls an **Athena Session**, which _contains many_ **Workflow Runs** and spawns _many_ vendor sessions. To make it worse, the protocol prose ("each **session** is a fresh process with no memory of prior **sessions**") uses _session_ for a single **Turn**. So one word means three things: **Athena Session** (infra durable container), Turn (protocol), and the vendor's actual session/thread. **Recommendation:** reserve **Session** for the vendor concept (**Agent Session**); qualify the durable identity as the **Athena Session** (which contains **Workflow Runs**); in the protocol replace "session" with **Turn**.
- **"Iteration" is not a vendor term and is redundant with Turn.** Neither vendor defines it; Anthropic documents "the agentic loop," not iterations. In Athena, one iteration _is_ one Turn. **Recommendation:** keep **Turn** as the unit and use "iteration" only as its integer index ("Turn 3 / iteration 3"), never as a separate concept.
- **"Turn"** is the one unit that already aligns: Codex defines it formally (`turn.*` events; one `thread.run` == one turn) and Athena's `startTurn`/`TurnExecutionResult` match it. Standardize everything onto **Turn**.
- **"Run"** is overloaded across **Workflow Run** (the loop, `workflow_runs` row), **Feed Run** (UI-timeline unit bounded by a trigger), and casual "run" for a single **Turn**. The two formal Runs even have different status enums (`completed/failed/cancelled` vs `aborted`). Always qualify _Workflow Run_ vs _Feed Run_; never let "run" mean a Turn.
- **"State machine"** names two things: the agent-facing **Turn Protocol** and the **Runner**'s loop. Say which.
- **"Stateless" in _Stateless Turn Protocol_ was a partial misnomer, now resolved.** A Turn that **resumes** its **Agent Session** (a **Nudge**, a **Retry**, a human reply) is not memoryless — only Turn 1 and the Turn opening a **Handover** start clean. ADR 0014 deferred the rename to avoid a ripple across ADR 0003, the protocol file, and the docs; ADR 0015 §11 executed it — the protocol is now the **Turn Protocol** everywhere (`stateMachine.md`, `stateMachine.ts`, `journalReader.ts`, `workflowRunner.ts`, this glossary, `CONTEXT-MAP.md`). "Stateless" survives only as a historical alias to avoid, not the live name.
- **"Compaction"** — vendor-defined as summarizing history _within the same Agent Session_. Athena's "a fresh Turn is self-compaction" is an analogy. Reserve **Compaction** for the in-Session mechanism; call the loop's reset the _fresh-Turn reset_.
- **Workflow Instructions vs Composed System Prompt** — `workflow.md` (authored) is not what reaches the agent; the **Composed System Prompt** (Protocol + instructions, regenerated per Workflow Run) is. Don't conflate source file with delivered artifact.
